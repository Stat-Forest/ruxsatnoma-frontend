# Статус-машины

Приложение 5 оригинала.

## Статусы заявки

| Статус | Описание | Возможные следующие статусы | Кто переводит |
|---|---|---|---|
| `DRAFT` | Черновик, сохранён через autosave | `SUBMITTED`, `CANCELLED` | Заявитель |
| `SUBMITTED` | Подписана ЭЦП и отправлена, зарегистрирована | `IN_REVIEW`, `RETURNED`, `REJECTED` | Система (автоматически), сотрудник-исполнитель |
| `IN_REVIEW` | Рассматривается | `PENDING_INFO`, **`CONTRACT_DRAFT`**, `APPROVED`, `REJECTED`, `RETURNED` | Сотрудник-исполнитель |
| `PENDING_INFO` | Запрошена дополнительная информация (**SLA-таймер остановлен**) | `IN_REVIEW`, `CANCELLED` | Сотрудник-исполнитель, заявитель |
| `RETURNED` | Возвращена на исправление | `SUBMITTED`, `CANCELLED` | Заявитель |
| `APPROVED` | Утверждена руководителем | `INVOICED` | Руководитель |
| `INVOICED` | Инвойс сформирован, ожидается платёж | `PAID`, `EXPIRED_UNPAID`, `CANCELLED` | Система |
| `PAID` | Платёж принят с подтверждением провайдера/банка | `PERMIT_ISSUED`, `REFUND_REQUESTED` | Система |
| `PERMIT_ISSUED` | Разрешение сформировано и подписано | `CLOSED` | Уполномоченное лицо |
| `REJECTED` | Отказано (с правовым основанием и причиной) | `ARCHIVED` | Руководитель |
| `CANCELLED` | Отменена заявителем | `ARCHIVED` | Заявитель |
| `EXPIRED_UNPAID` | Истёк срок оплаты | `ARCHIVED` | Система |
| `CLOSED` | Процесс завершён | `ARCHIVED` | Система |
| `ARCHIVED` | Переведена в архив | — | Система |

> ⚠️ **Пробел ТЗ.** Статус `CONTRACT_DRAFT` указан как возможный переход из `IN_REVIEW`, но **сам в таблице статусов отсутствует** — не определены его описание, следующие статусы и роль, которая его переводит. Аналогично статус `REFUND_REQUESTED` указан как переход из `PAID`, но отдельно не описан. См. [18-gaps-and-open-questions.md](18-gaps-and-open-questions.md).

## Статусы разрешения

| Статус | Описание | Возможные следующие статусы | Кто переводит |
|---|---|---|---|
| `ACTIVE` | Действует | `SUSPENDED`, `REVOKED`, `EXPIRED` | Руководитель, система |
| `SUSPENDED` | Приостановлено (с правовым основанием) | `ACTIVE`, `REVOKED`, `EXPIRED` | Руководитель |
| `REVOKED` | Аннулировано | `ARCHIVED` | Руководитель |
| `EXPIRED` | Срок истёк (автоматически) | `ARCHIVED` | Система |
| `ARCHIVED` | Переведено в архив | — | Система |

Автоматическая отметка истёкших разрешений выполняется **ежедневным регламентным заданием** (С13).

При смене статуса **пересчитываются занятость соответствующего контура и остаточный лимит**.

## Жизненный цикл GIS-контура и нормы

```
Draft → Review → Approved → Published → Archived
```

> Перевод в состояние `Published` осуществляется **только при наличии подтверждающего документа** (`approval_doc_id`).

Следствия:
- По контуру в статусе `Published` становится возможным ввод нормы, и он открывается для выбора в заявках (С17).
- Норма в статусе `Published` становится активной для заявок (С18).
- При изменении контура прежняя версия уходит в архив, **привязанные к ней разрешения сохраняются в привязке к старой версии** (С17, п. 17.4).
- При изменении нормы **разрешения, выданные за прежний период, сохраняются на основе старых `rule_version` и input snapshot и не пересчитываются** (С18, п. 18.3).

## Состояния платежа

```
CREATED → PENDING → PAID → RECONCILED
```

Альтернативные ветви: `FAILED`, `EXPIRED`, `REFUNDED`, `PARTIALLY_REFUNDED`.

Ключевое ограничение: **`PAID` устанавливается только на основании подтверждения провайдера или банка** (С9, п. 5). Ручная установка — только через maker-checker с подтверждающим банковским документом и автоматической генерацией `RI-01`.

---

## Состояния уведомления

```
QUEUED → SENT → DELIVERED
              ↘ FAILED
```

При `FAILED` выполняется повторная попытка через резервный канал; сотруднику формируется задание, если контактные данные неверны.

## Статусы акта инспекции

```
соответствует (мувофиқ) | предупреждение (огоҳлантириш) | нарушение (қоидабузарлик)
```

Статус «нарушение» автоматически передаётся в поток цифрового надзора и запускает сценарий С16.

---

## Статусы отчётной формы

```
Создана (Яратилган) → Утверждена (Тасдиқланган)
```

Дополнительные списки состояний: отправленные, возвращённые, принятые отчёты, черновики, просроченные.

Редактирование разрешено **только автору и только в статусе «Создана»**. Исправление после утверждения вносится **как отдельная версия**.

---

## Общее требование к любому переходу

> Каждое изменение статуса записывается в аудит с указанием: **кто, когда, с какого IP/устройства, на каком основании** выполнил переход, и передаётся в поток цифрового надзора.

Это означает, что переход статуса нельзя реализовать простым `UPDATE` — он должен быть обёрнут в транзакцию, которая одновременно пишет запись аудита и надзорное событие в outbox.

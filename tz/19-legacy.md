## Часть 1. Старое ТЗ 2021 года

Файл: `../ruxsatnoma-old-tz.pdf`, 67 страниц, создан в апреле 2021 (Acrobat PDFMaker 19 для Word), изменён в сентябре 2021.

### Основные сведения

| | |
|---|---|
| Полное наименование | Система выдачи онлайн-билетов (разрешений) на выпас скота на пастбищных землях лесного фонда и сенокошение |
| Условное наименование | «Рухсатнома» АТ |
| Код системы | `00011558.РухсатномаАТ.Б02` |
| Заказчик | **Государственный комитет по лесному хозяйству** (Ташкентская обл., Кибрайский р-н, ул. Университетская, 2) |
| Исполнитель | **ГУП «Ўрмонтехносервис»** (тот же адрес, ИНН 305 638 965) |
| Сроки | Начало 1 января 2021, окончание 1 декабря 2021 |
| Организаций системы | **115** |
| Правовые основания | ПФ-6079 от 05.10.2020, ВМҚ 290-сон от 20.10.2014 |

Сопроводительное письмо от 20 января 2020 г. № 04124-1ZL адресовано Министерству по развитию информационных технологий и коммуникаций и ГУП «Центр кибербезопасности» для получения экспертного заключения. В том же пакете было **второе ТЗ — на аукционный портал сдачи земель лесного фонда в аренду на основе государственно-частного партнёрства** (сейчас это, по-видимому, `billing-urmon.uz`).

### Назначение (п. 2.1 старого ТЗ)

1. Цифровизация деятельности Комитета
2. Онлайн-мониторинг работ по выдаче разрешений
3. Онлайн-выдача разрешений
4. Ведение учёта пастбищных земель
5. Формирование данных по скоту на пастбищных землях и его численности

### Подсистемы старого ТЗ (11)

1. Администрирование
2. Logging — журналирование каждого действия
3. Отчёты
4. База данных
5. Поиск
6. Контроль доступа
7. Пользовательский интерфейс
8. Информационно-аналитическая
9. Разрешение
10. Применение ЭЦП
11. Взаимодействие с соответствующими ИС

### Внешние системы старого ТЗ (всего 3)

1. Платформа межведомственной интеграции «Электронное правительство»
2. БД физических лиц Государственного центра персонализации при Кабинете Министров — для автозаполнения при регистрации (Ф. И. О., гражданство, дата и место рождения)
3. Электронные платёжные системы

### Сценарии старого ТЗ (всего 2)

| ID | Название |
|---|---|
| `U1` | Регистрация на портале для получения электронного разрешения |
| `PP1` | Выдача разрешения на выпас скота на пастбищных землях лесного фонда |

Шаги `PP1`:
1. Ознакомление с условиями подачи заявки (публичная оферта)
2. Подача заявки физ./юрлицом и подтверждение ЭЦП
3. Изучение поступивших заявок и документов
4. Оформление исполнителем на местах представленных документов
5. Показ предлагаемого участка заявителю *(в системе не выполняется)*
6. **Отправка и оформление договора** (образец договора уточняется в процессе разработки)
7. Проверка факта оплаты
8. Подтверждение разрешения через ЭЦП
9. Предоставление разрешения физ./юрлицу

> Шаг 6 — прямое подтверждение гипотезы о том, что отсутствующий модуль 10.4 и сценарий С7 нового ТЗ — это договор.

### Категории пользователей старого ТЗ (4)

1. Пользователи электронного портала (физ. и юрлица)
2. Исполнители на местах
3. Просматривающие статистику и мониторинг (центральный аппарат)
4. Системные администраторы

### Поля разрешения в старом ТЗ

**По лесному хозяйству:** название хозяйства (выбор), лесничество (выбор), обход (ввод), квартал (ввод), выделенная площадь (га, ввод).

**По пользователю:** Ф. И. О. (ввод), номер паспорта (ввод), адрес (ввод), общее число скота (ввод), КРС/овцы/лошади/козы/верблюды/ослы (ввод).

**По разрешению:** срок пользования (выбор), Ф. И. О. руководителя хозяйства, Ф. И. О. главного лесничего, Ф. И. О. главного бухгалтера, печать подлинности — QR-код.

### Перспективы, заявленные в старом ТЗ

> «На последующих этапах развития информационной системы необходимо внедрить **геоинформационную подсистему** и создать в ней возможность формирования контуров площадей, выделенных из пастбищных земель лесного фонда для выпаса скота. Благодаря этому будет достигнута полная автоматизация процесса выдачи разрешений.»

То есть GIS изначально планировался как второй этап — и новое ТЗ его реализует.

## Часть 2. Обследование действующей платформы

Проведено 7 августа 2026. Публичный осмотр без авторизации.

### Технологический стек

| Компонент | Что обнаружено |
|---|---|
| Веб-сервер | `nginx/1.22.1` |
| Бэкенд | **Django** (cookie `csrftoken`, хешированные имена статики `bootstrap.316236780c77.css`) |
| Фронтенд | Django templates + **jQuery 3.6.0** + **Bootstrap 5.0.0-beta1** + FontAwesome 5.15.1 |
| Отдельного SPA-фронтенда | **нет** |
| CSP | Настроен, разрешает `https://billing-urmon.uz`, `wss://127.0.0.1:64443`, `wss://127.0.0.1:64646` |

Порты `64443` и `64646` в CSP — локальный websocket **E-IMZO**, то есть подпись ЭЦП в системе работает.

### Маршруты

| Маршрут | Назначение |
|---|---|
| `/` | Главная: подача заявки, FAQ, проверка статуса заявки по номеру `A-*****`, территориальные управления, оценка портала |
| `/ipsgov` | Регистрация: **ЖШШИР + серия и номер паспорта + телефон → SMS-код**. Согласие по ст. 18 Закона «О персональных данных» (ЎРҚ-547), данные через платформу межведомственной интеграции «Электронное правительство» |
| `/insp-login` | Вход для сотрудников: логин + пароль, **без MFA** |
| `POST /api/v1/auth/idgovuz` | Вход через **OneID** |
| `POST /eimzo-login` | Вход через **E-IMZO** |
| `/info` | Открытые данные ведомства (ссылки на `data.egov.uz`) |
| `/polls/1/vote/` | Оценка качества портала |

`/admin/`, `/api/`, `/swagger/`, `/robots.txt`, `/sitemap.xml` — закрыты или отсутствуют.

### Что уже работает и переиспользуемо концептуально

- Регистрация по ЖШШИР + паспорт с автозаполнением из госреестра через ИМУТ
- Вход через OneID
- Вход через E-IMZO
- Публичная проверка статуса заявки по номеру
- Форма оценки услуги (KPI «удовлетворённость ≥ 4,5/5»)

### Чего нет вообще

GIS, rule engine, платёжный контур внутри системы, инспекторский модуль, отчёты, dashboard, аудит, архив, лесной билет, my.gov.uz, контур цифрового надзора, MFA.

> По сути действующая платформа покрывает **2 сценария из 27** нового ТЗ — те самые `U1` и `PP1` старого ТЗ.

### Смежная система: `billing-urmon.uz`

**«Ijaraga berilgan o'rmon fondi yerlari hisobini yuritish axborot-billing tizimi»** — информационно-биллинговая система учёта арендованных земель лесного фонда.

| | |
|---|---|
| Фронтенд | **Nuxt** (заголовок `x-powered-by: Nuxt`) |
| Веб-сервер | `nginx/1.22.1` (тот же) |
| Вход | JSHSHIR + пароль, **OneID**, **E-IMZO** |
| Язык интерфейса | Узбекская **латиница** (в отличие от `ruxsatnoma-urmon.uz`, где кириллица) |

Это отдельный продукт того же ведомства — вероятно, реализация второго ТЗ из пакета 2021 года (аукционный портал аренды земель лесфонда на основе ГЧП). В новое ТЗ Ruxsatnoma не входит, но действующая платформа ссылается на него в CSP (`connect-src`), то есть платёжный контур сейчас вынесен туда.

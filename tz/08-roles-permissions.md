# Роли и права доступа

Пункт 4.2.13 и приложение 4 оригинала. Отдельная матрица прокурора — приложение 6.1.

## Роли и основные полномочия (10 ролей)

| № | Роль | Основные полномочия |
|---|---|---|
| 1 | **Системный администратор** | Полное управление системой; управление пользователями, ролями, организациями и классификаторами; настройка параметров системы; резервирование и восстановление данных; просмотр журналов (**удалять не может**) |
| 2 | **Сотрудник центрального аппарата** (админ отдела) | Управление отчётными формами и сроками; приём и возврат поступивших отчётов; мониторинг и анализ по республике |
| 3 | **Руководство** | Мониторинг и анализ во всех разрезах; просмотр сводных отчётов |
| 4 | **Сотрудник организации-исполнителя** | Приём и рассмотрение заявок; оформление документов; заполнение отчётов |
| 5 | **GIS/нормативный специалист** | Ввод и версионирование GIS-контуров; ввод нормы, лимита и тарифа; выдача заключения по проверке |
| 6 | **Руководитель организации-исполнителя** (уполномоченное лицо) | Принятие решения по заявке; подписание разрешения ЭЦП; утверждение отчётов; приостановка и аннулирование разрешения |
| 7 | **Инспектор** | Полевой мониторинг; проверка по QR; составление и подписание электронного акта; фиксация нарушения |
| 8 | **Бухгалтер** | Отслеживание инвойсов и платежей; reconciliation; распределение; учёт refund |
| 9 | **Физическое и юридическое лицо** (заявитель) | Регистрация; подача заявки; оплата; получение разрешения; отправка обращения |
| 10 | **Прокурор** | Присваивается **после верификации в «Raqamli nazorat»**. Просмотр, поиск, фильтрация, анализ и формирование отчётов **только в Read-Only режиме** по всем заявкам, разрешениям, платежам, GIS, нормам, инспекциям и данным аудита в пределах кода территории. **Никаких полномочий на создание, изменение, удаление, утверждение или подписание** |

### Техническое усиление Read-Only — три уровня

> Дословное требование приложения 6:

1. **На уровне интерфейса** — изменяющие элементы не показываются.
2. **На уровне API** — открыты только методы `GET`, все write-endpoint'ы закрыты для роли.
3. **На уровне СУБД** — для роли отдельный пользователь `read_only` и view'ы, права `INSERT`/`UPDATE`/`DELETE` не выдаются.

Дополнительно из п. 4.1.6:

| Требование | Значение |
|---|---|
| Канал входа | Только выделенная веб-страница через ИМУТ; вход из публичного интернета закрыт; IP allowlist; **отдельный домен/поддомен** |
| Аутентификация | ЭЦП E-IMZO или OneID; **вход по паролю запрещён**; TTL сессии ≤ 30 минут, требуется повторная аутентификация |
| Верификация | При **каждом** входе — живая верификация по ЖШШИР в «Raqamli nazorat»; роль присваивается только по положительному ответу; **ответ не кэшируется** |
| Минимизация данных | Персональные данные — в пределах необходимости; лишние поля маскируются; полное раскрытие — с отдельным основанием и отметкой |
| Контроль экспорта | Объём экспорта ограничивается, проставляются watermark и ID пользователя, каждый экспорт записывается в аудит и в «Raqamli nazorat» |
| Взаимный контроль | Действия и прокурора, и системного администратора попадают в один и тот же append-only аудит; **ни одна роль не может удалить аудит** |

### Требования к интерфейсу роли «Прокурор» (п. 4.1.7)

Интерфейс работает полностью в Read-Only режиме: **не показываются** кнопки, формы и контекстные меню, относящиеся к добавлению, редактированию, удалению, утверждению, отказу, изменению состояния процесса, замене файла и импорту.

Прокурору предоставляются возможности мониторинга, просмотра, поиска, фильтрации, сравнения, формирования отчётов и скачивания в разрешённых форматах.

> Общее требование п. 4.1.7: пользователю показываются только те меню, страницы и элементы управления, которые нужны для выполнения его задач. **Не допускается показывать кнопку операции, на которую нет права, а затем выводить сообщение об ошибке.**

## Категории пользователей и их численность (п. 4.1.3)

Пользователи делятся на 5 групп:

1. физические и юридические лица, обращающиеся через публичный портал / my.gov.uz;
2. исполнители на местах (принимающий заявки, рассматривающий, GIS и нормативный специалист, инспектор);
3. центральный аппарат — просматривающие статистику и мониторинг, руководство;
4. системные администраторы;
5. сотрудники органов прокуратуры (роль «Прокурор»).

| Категория | Количество |
|---|---|
| Исполнители на местах (территориальные управления, лесхозы) | до **300** |
| Пользователи электронного портала / my.gov.uz (физ. и юрлица) | до **10 000**, ежегодно ≥ **30 000 заявок** |
| Центральный аппарат и руководство | до **50** |
| Системные администраторы | **5–10** |
| Сотрудники органов прокуратуры (роль «Прокурор») | от **1 до 100** |

### Требования к квалификации и режиму

| Роль | Требование | Режим |
|---|---|---|
| Администратор системы и инфраструктуры (сервер, сеть, БД, безопасность) | Определяется техническим регламентом работы в системе | Дежурство 24/7 либо вызов по SLA |
| Поддержка пользователей (support/helpdesk) | Обучены по руководствам пользователя | В течение рабочего дня, ответ по SLA |

Администратор обеспечивает целостность БД и программ, профилактические меры по безопасности данных, управление информационными потоками, организацию взаимодействия всех категорий пользователей с системой и централизованное управление модулями и функциями.

Для всех категорий пользователей должно быть организовано предварительное обучение (**train-the-trainer**).

Для пользователей роли «Прокурор» разрабатываются отдельное обучение и инструкция; их учётные записи **автоматически приостанавливаются по истечении срока полномочий в «Raqamli nazorat»**.

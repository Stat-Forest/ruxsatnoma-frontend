# Интеграции с внешними системами

Пункты 4.1.1.2 и 4.1.2 оригинала.

## Канал связи

Для связи с внешними системами требуется канал через межведомственную сеть **не менее 2 Мбит/с**.

Межсетевое взаимодействие — на открытых стандартах на базе протоколов TCP/IP. Обмен информацией между подсистемами — по государственным стандартам **O'z DSt 1135** и **O'z DSt 2590**.

Межведомственная интеграция осуществляется через **Платформу межведомственной интеграции** согласно **O'z DSt 2864** (при принятии нового стандарта — по действующему).

Интеграция с ИС министерств и ведомств выполняется после утверждения соглашения о взаимодействии и технологической инструкции.

## Обязательный состав интеграции с «Raqamli nazorat»

Это единственная интеграция, контракт которой зафиксирован в ТЗ на уровне методов.

| Направление | Метод | Содержание |
|---|---|---|
| АТ → RN | `POST /registration` | Регистрация системы/ресурса: имя, владелец, ID системы/ресурса, версия, ответственное лицо, интеграционный сертификат |
| АТ → RN | `POST /verify-officer` | Запрос верификации сотрудника прокуратуры по ЖШШИР |
| RN → АТ | Ответ | Статус (подтверждён/отклонён), должность, код территории, срок полномочий, уровень роли |
| АТ → RN | `POST /events` | Юридически значимые события: утверждение, подпись, платёж, изменение тарифа/нормы, отказ, аннулирование |
| АТ → RN | `POST /risk-indicators` | Автоматически выявленные риск-индикаторы (по приложению 6) |
| АТ → RN | `POST /access-log` | Журнал действий прокурора: просмотр, поиск, экспорт |
| RN → АТ | `GET /dataset` | Запрос агрегированных или детальных данных в разрезе территории и периода (Read-Only) |

### Технические требования к этой интеграции

- **mTLS** и сообщение, подписанное ЭЦП.
- Обязательны **`Idempotency-Key`** и **`Correlation-Id`**.
- Направление, дата, время и контрольная сумма каждого сообщения протоколируются.
- Транспорт — **только через ИМУТ, не через публичный интернет**.
- При обрыве применяются механизмы **outbox и retry**, данные не теряются.
- Недоставленные сообщения попадают в **DLQ**, администратору отправляется предупреждение.

## Формы обмена данными (п. 4.1.2)

Система должна предусматривать следующие формы обмена:

- экспорт и импорт данных;
- защищённое удалённое подключение к базе данных (с разрешения администратора);
- подключение по технологии веб-сервисов: **REST/JSON, GeoJSON, SOAP/XML, WSDL, UDDI**;
- программные интерфейсы **ADO, ODBC, OLE DB**;
- протоколы **TCP/IP, HTTP/HTTPS**;
- почтовые протоколы **SMTP, IMAP**;
- синхронные и асинхронные службы обмена сообщениями;
- подключение через **REST API (.json)**.

**Протоколирование обязательно:** программные средства веб-сервиса должны протоколировать по каждому сообщению — факт приёма и отправки, направление, дату, время, получателя и контрольную сумму сообщения.

Применение справочников и классификаторов должно предусматривать использование реестра справочников и классификаторов «Электронного правительства» — **cs.egov.uz**.

Все правила по электронным платёжным системам регулируются соответствующими техническими инструкциями; эти инструкции определяются как **неотъемлемая часть** разработки системы.

## Требования к подсистеме интеграции (п. 4.2.9)

Подсистема должна выполнять:

1. Приём и отправку поступивших запросов и документов.
2. Отправку ответов на запрос — с кодами ошибок или статусом доставки.
3. Протоколирование направления, даты, времени, получателя и контрольной суммы каждого сообщения.
4. Обеспечение надёжной доставки: **outbox, retry + exponential backoff, circuit breaker, DLQ, idempotency**.
5. Ведение и версионирование интеграционных контрактов (**OpenAPI/AsyncAPI**).
6. Мониторинг состояния интеграций и отправку предупреждений.
7. Тестирование интеграции в среде **sandbox**.

### Регламент времени

| Параметр | Значение |
|---|---|
| Timeout синхронного запроса | ≤ 10 секунд |
| Retry | Экспоненциальный: 1, 2, 4, 8… минут |
| Предупреждение по DLQ | Немедленно |
| Синхронные запросы | Немедленно |
| Асинхронные события | В течение 5 минут |
| Восстановление интеграции при сбое | 8 часов (данные не теряются через outbox) |

### Мониторинг на dashboard

Число запросов, доля ошибок, среднее время ответа, объём DLQ.

# Математическое обеспечение и формулы

Пункт 4.3.1 оригинала.

## Общие требования

Математическое обеспечение основывается на действующих НПА: **ВМҚ 278-сон, ВМҚ 506-сон, ВМҚ 689-сон** и **Закон «О лесе»**.

> Все расчёты выполняются в **decimal-арифметике**, с точной единицей измерения и политикой округления (**rounding policy**), с сохранением `rule_version` и **input snapshot**.

В случаях, не урегулированных нормативными документами, применяются логически оптимальные математические методы, модели и алгоритмы.

Математическое обеспечение должно также включать стандартные и созданные методы и алгоритмы сбора и обработки информации, алгоритмы поиска и упорядочивания данных.

## Основные расчётные формулы

| Расчёт | Формула / правило | Примечание |
|---|---|---|
| **Остаточная площадь** | `S_available = S_total − S_active_overlap` | Геометрия активных разрешений с пересекающимся периодом; **устраняется двойной учёт (double-count)** |
| **Запас корма** | `Oz = Yield_c_per_ha × Area_ha × Season_share` | С продолжительностью календаря по ВМҚ 689-сон |
| **Эффективный запас** | `Oz_eff = Oz × 0,85` | **15 % страховой фонд** |
| **Максимум условных голов** | `MaxSB = floor(Oz_eff / 3,74)` | 3,74 центнера кормовых единиц |
| **Нагрузка заявки** | `UsedSB = Σ Count_i × CoefSB_i` | `CoefSB` — из приложения 5 к ВМҚ 689-сон |
| **Остаточный лимит** | `RemainingSB = MaxSB − ActivePermitsSB`<br>условие: `UsedSB ≤ RemainingSB` | **Обязательно проверяется перед отправкой заявки** |
| **Платёж** | `Amount = БҲМ × coefficient × quantity` | Коэффициент и БҲМ — из ВМҚ 278-сон, с `effective_date` |
| **Возврат (refund)** | `Refund = Paid × unused_eligible_period / paid_period` | На основании пп. 9–11 ВМҚ 278-сон |
| **Распределение** | `Allocation = Amount × 0,5` (для каждого получателя) | Соотношение **50/50**, фиксируется в allocation ledger |
| **Расстояние инспектора** | Ортодромическое расстояние (`ST_Distance` геодезический) | Между GPS-точкой инспектора и границей контура |

## Разбор цепочки расчёта нормы

Порядок вычисления при вводе нормы (сценарий С18):

```
1. Геоботаническое исследование  →  Yield_c_per_ha (урожайность, ц/га)
2. GIS-контур                    →  Area_ha (площадь, га)
3. Календарь сезона (ВМҚ 689)    →  Season_share (доля сезона)
                                     ↓
4. Oz     = Yield_c_per_ha × Area_ha × Season_share     [запас корма, ц]
5. Oz_eff = Oz × 0,85                                    [минус 15 % страховой фонд]
6. MaxSB  = floor(Oz_eff / 3,74)                         [максимум условных голов]
                                     ↓
7. Сохранить как норму с rule_version, effective_from/to, approval_doc_id
```

Порядок вычисления при подаче заявки (сценарий С3):

```
1. Выбранный контур + период
                ↓
2. ActivePermitsSB  =  Σ SB активных разрешений на контуре
                       с пересекающимся периодом
3. RemainingSB      =  MaxSB − ActivePermitsSB
                ↓
4. UsedSB           =  Σ Count_i × CoefSB_i     (по составу скота в заявке)
                ↓
5. Проверка: UsedSB ≤ RemainingSB ?
       нет → ошибка ERR-NORM-002, отказ RJ-05
             показать RemainingSB и максимально возможное поголовье
       да  → продолжить
                ↓
6. Amount = БҲМ × coefficient × quantity
7. Сохранить calculation_snapshot + rule_version
```

## Состав условных голов

Разбивка поголовья, требуемая формой разрешения (приложение 1) и отчётной формой (приложение 2):

| Группа | Виды |
|---|---|
| Взрослые | крупный рогатый скот, лошади, верблюды, ослы |
| Молодняк до 2 лет | крупный рогатый скот, лошади, верблюды, ослы |
| Старше 6 месяцев | овцы, козы |
| До 6 месяцев | ягнята, козлята |

Коэффициенты приведения `CoefSB_i` для каждой группы берутся из **приложения 5 к ВМҚ 689-сон**.

> ⚠️ Сами значения коэффициентов в ТЗ не приведены — их нужно взять из текста ВМҚ 689-сон. См. [18-gaps-and-open-questions.md](18-gaps-and-open-questions.md).

## Требования к реализации расчётов

Из п. 4.2.15 и п. 4.2.10 (модуль 10.3):

- **Воспроизводимость** — при одинаковых входных данных результат всегда одинаков.
- **Объяснимость** — каждый расчёт хранится с `rule_version` и `input_snapshot`, чтобы можно было восстановить, откуда взялось число.
- **Норма и тариф версионируются** с `effective_from` / `effective_to`.
- **Ретроактивное изменение** нормы или тарифа требует **maker-checker** и формирует риск-индикатор `RI-04`.
- При изменении нормы **ранее выданные разрешения не пересчитываются** — они сохраняются на старой версии.
- Расчёт вне формулы блокируется: для refund — с формированием `RI-11`, для превышения нормы — `RI-02`.

## Требования к времени расчёта

| Операция | Регламент |
|---|---|
| Проверка overlap и лимита (server-side) | ≤ 5 секунд |
| Расчёт нормы | ≤ 3 секунды |
| Расчёт возврата | ≤ 5 секунд |
| Распределение платежа | ≤ 5 секунд |

## Метрология (п. 4.3.6)

Отдельные метрологические требования не предусмотрены. При этом должны обеспечиваться:

- точность GPS-координат;
- погрешность измерения площади;
- получение меток времени из **единого источника (NTP)**.

> Метки времени хранятся в **единой временной зоне UTC+5** и отображаются в интерфейсе в местном времени.

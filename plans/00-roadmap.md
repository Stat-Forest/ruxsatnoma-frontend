# Дорожная карта Ruxsatnoma

> **Для агентов:** это карта верхнего уровня. Детальные планы всех фаз написаны и лежат рядом — `phase-N-*.md`. Там, где требование зависит от неотвеченного вопроса Заказчика, это помечено ⚠️ с указанием кода вопроса.

**Цель:** заменить действующий Django-монолит системой по новому ТЗ — 12 подсистем, 27 сценариев, 12 интеграций, без потери данных.

**Подход:** два бэкенд-сервиса (`core`, `integration`) и фронтенд на Next.js. Идём снизу вверх: фундамент → данные и правила → ядро процесса → деньги → контроль → витрины → миграция → приёмка.

**Стек:** PostgreSQL 18 + PostGIS 3.6, Redis, RabbitMQ, MinIO, nginx, Next.js.

## Глобальные ограничения

Действуют в каждой задаче каждой фазы. Значения взяты из ТЗ дословно.

- Деньги — только `numeric(18,2)`, decimal-арифметика, явная политика округления. Никогда `float` и `int`.
- Время — только `timestamptz`, хранение UTC, отображение UTC+5, источник NTP.
- Каждое действие пишет запись в `audit.audit_log` **в той же транзакции**, что и само действие.
- Каждый расчёт хранится с `rule_version` и `input_snapshot`. Одинаковый вход даёт одинаковый результат.
- Аудит append-only. Ни одна роль, включая администратора, не может изменить или удалить запись.
- Ограничения целостности — на уровне СУБД, а не приложения: дубликаты, уникальность номера разрешения, связь разрешения с геометрией.
- Все внешние вызовы — только через `integration`, с `Idempotency-Key` и `Correlation-Id`, через outbox с retry и DLQ.
- Производительность: p95 API ≤ 500 мс, GIS ≤ 3 с, проверка лимита ≤ 5 с, поиск ≤ 3 с, при 1000 одновременных пользователей.
- Доступность ≥ 99,7 %, RPO ≤ 15 минут, RTO ≤ 4 часа.
- Интерфейс: responsive, WCAG 2.2 уровня AA, узбекская кириллица как основной язык.
- Каждый ответ API использует коды ошибок из приложения 8 ТЗ: `ERR-AUTH-*`, `ERR-ACL-*`, `ERR-APP-*`, `ERR-GIS-*`, `ERR-NORM-*`, `ERR-PAY-*`, `ERR-SIGN-*`, `ERR-INT-*`, `ERR-SYS-*`.
- Язык — Python, фреймворк FastAPI. Инженерные стандарты, стек, правила тестирования и конфигурация инструментов — в [`../architecture/engineering-standards.md`](../architecture/engineering-standards.md). Имена в коде берутся из единого языка, а не изобретаются.
- **В коде только английский** — имена, комментарии, docstring-и, тексты исключений, коммиты, ветки, миграции, ключи логов. Тексты для пользователя — в `locales/`. Проверяется в CI.
- Порядок работы — TDD: падающий тест, минимальная реализация, зелёный тест, рефакторинг, коммит. Для формул и статус-машины это обязательно.
- Красный CI — код не вливается. Ни один шаг проверки не пропускается.

## Оценка сроков

**Назначенный срок завершения всех работ — 20 августа 2026.** Решение техлида от 10 августа 2026, вопрос **Р1**. Основание — применение средств разработки с ИИ.

### Исходная оценка

Составлена в человеко-неделях на команду из четырёх человек, сохраняется для сравнения:

| Фаза | Недель |
|---|---|
| 0 | 3–4 (август, параллельно с экспертизой) |
| 1 | 3 |
| 2 | 3 |
| 3 | 4 |
| 4 | 3 |
| 5 | 3 |
| 6 | 3 |
| 7 | параллельно 5–6 |
| 8 | 2 |

Сумма фаз 1–8 — 21 неделя. По ТЗ доступно 17 (сентябрь–декабрь).

### Подённая раскладка

**Пересчитана и вынесена в отдельный файл: [`schedule-august-2026.md`](schedule-august-2026.md).** Там распределение всех 104 оставшихся задач по 11 дням и пяти исполнителям, контрольные точки и риски.

Коротко: 10–20 августа, **~9,5 задачи в день** на команду, то есть по две на человека. Сжатие относительно исходной оценки примерно пятнадцатикратное.

### Что не сжимается вместе с разработкой

Эти сроки не зависят от темпа Исполнителя:

| Что | Почему не сжимается |
|---|---|
| Опытная эксплуатация | От 5 до 15 рабочих дней силами Заказчика, задача 8.2 |
| Приёмочные испытания | По «Программе и методике испытаний», задача 8.3 |
| Обучение администраторов | Задача 8.5 |
| Ответы Заказчика на 5 блокеров | Б1, Б2, Б3, Б5, Н3 — сроки задают внешние организации |
| Экспертиза ТЗ | Этап 3 раздела 5 ТЗ, август–сентябрь 2026 |
| Ввод контуров и норм | Задача Заказчика, ведётся вне системы |

Даже нижняя граница опытной эксплуатации — 5 рабочих дней — это 7 календарных. Чтобы акт был подписан 20 августа, разработку следовало бы завершить 13 августа. Поэтому в фазу 0 добавлена задача **0.16**: согласовать с Заказчиком сжатый график приёмки. Без его ответа дата 20 августа упирается в процедуру, а не в скорость разработки.

### При отставании

Решение техлида: **объём и глубина проработки не сокращаются, переносится дата.** Задачи не выбрасываются, шаги проверки не пропускаются, при красном CI ничего не вливается.

### Очерёдность видов деятельности

Первая очередь — выпас скота и сенокошение (вопрос **О5**, закрыт 10 августа). Причина деления теперь не срок, а отсутствие утверждённых форм для остальных четырёх видов (вопрос **П6**, открыт). Механика делается сразу под все шесть: состав полей задаётся данными, а не кодом.

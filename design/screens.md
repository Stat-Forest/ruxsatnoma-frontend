# Карта экранов

Что видит каждая роль и из чего состоит каждый экран. Основано на 10 ролях из [`../tz/08-roles-permissions.md`](../tz/08-roles-permissions.md) и требовании п. 4.1.7 ТЗ: пользователю показываются только те меню и элементы, которые нужны для его задач.

> **Правило, которое проверяется на ревью:** не допускается показывать кнопку операции, на которую нет права, а затем выводить сообщение об ошибке. Если права нет — элемента нет.

---

## Общая структура

Требование п. 4.1.7 задаёт минимальный состав интерфейса. Ниже он разложен по трём группам маршрутов Next.js.

```
(public)     без авторизации, SSR для индексации
(cabinet)    личные кабинеты по ролям
(field)      PWA инспектора, работает offline
```

### Мастер подачи заявки

Самый ответственный экран системы.

| Шаг | Что происходит |
|---|---|
| **1. Вид деятельности** | Шесть карточек. Выбор определяет состав следующих шагов |
| **2. Участок** | Иерархия: область → район → лесхоз → лесничество → обход → квартал → контур. Либо выбор на карте. Сразу показывается свободная площадь и остаток лимита |
| **3. Параметры** | Период, площадь, состав скота по 12 группам либо параметры другого вида деятельности. **Расчёт пересчитывается на лету** |
| **4. Документы** | Загрузка приложений: ветеринарная справка, документ о льготе, доверенность. Проверка формата и размера |
| **5. Проверка** | Итог перед подписью: участок, период, поголовье, сумма **с расшифровкой откуда она взялась** — норма, `MaxSB`, `RemainingSB`, `UsedSB`, тариф |
| **6. Подпись** | ЭЦП через E-IMZO, отправка, номер заявки |

Автосохранение на каждом шаге. Возврат назад без потери данных. Предупреждение при уходе со страницы.

## Инспектор — PWA

Сценарии **С15**, **С16**. Работает offline.

| Экран | Что на нём |
|---|---|
| **Задания** | Список на сегодня, маршрут, состояние синхронизации |
| **Сканер QR** | Камера, при отказе — ручной ввод номера. Проверка из локального кэша, если нет связи |
| **Разрешение — проверка** | Статус, реквизиты, разрешённый контур на карте, **GPS-позиция и расстояние до контура** |
| **Акт инспекции** | Чек-лист, фактическое поголовье, занятая площадь, сравнение с нормой, фото и видео, примечание, подпись ЭЦП. Статус: соответствует, предупреждение, нарушение |
| **Съёмка** | Камера с автоматическим прикреплением времени, GPS, устройства и hash |
| **Нарушения** | Дела, сроки объяснения, решения |
| **Синхронизация** | Что не отправлено, конфликты, ручной запуск |

**Offline-состояния — отдельная работа.** У каждого экрана три вида: онлайн, offline с кэшем, offline без кэша. Третий должен объяснять, что доступно, а не показывать пустоту.

## Прокурор — закрытый периметр

Сценарий **С22**. Отдельный домен, доступ только через ИМУТ.

| Экран | Что на нём |
|---|---|
| **Вход** | Только E-IMZO или OneID. **Пароль недоступен как способ входа** |
| **Витрина** | Заявки, разрешения, платежи, GIS, нормы, инспекции, аудит — в пределах своей территории |
| **Поиск** | ЖШШИР, СТИР, номер разрешения, ID контура, территория, период, статус, сумма, ответственный, тип риска |
| **Аналитика** | Готовые разрезы: нарушения SLA, разрешения сверх лимита, ручные отметки оплаты, пересекающиеся контуры, ретроактивные изменения тарифов |
| **Риск-индикаторы** | `RI-01`…`RI-15` с фильтрами по коду, уровню, периоду |
| **Объект — карточка** | Полные реквизиты, история статусов, метаданные аудита: кто, когда, с какого IP, на каком основании |
| **Экспорт** | PDF и XLSX с watermark и ID пользователя, с лимитом объёма |

**Интерфейс полностью Read-Only.** По п. 4.1.7 не показываются кнопки, формы и контекстные меню добавления, редактирования, удаления, утверждения, отказа, смены состояния, замены файла и импорта. Их нет в разметке, а не скрыты стилями.

Девяносто четыре экрана на одного фронтендера за четыре месяца — это примерно один экран в рабочий день без учёта состояний, offline-режима и адаптива.

**Вывод для планирования:** объём фронтенда — самостоятельный аргумент за поэтапный ввод. Первая очередь по вопросу **О5** сокращает публичную часть и мастер подачи заявки до двух видов деятельности, но не уменьшает число экранов администратора, бухгалтера и прокурора — они нужны целиком с первого дня.

Это стоит зафиксировать в ответе Заказчику на вопрос **О5**.

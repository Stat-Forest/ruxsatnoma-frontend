# Дизайн-система

Дизайна у проекта не было. Этот документ — его основа: токены, шкалы, компоненты и состояния, из которых собирается весь интерфейс.

Требования ТЗ, которые здесь выполняются, — п. 4.1.7 «Эргономика и техническая эстетика»: единая дизайн-система во всех модулях, 2–3 основных цвета на модуль, responsive от 1170×768, **WCAG 2.2 уровня AA**, состояние объясняется не только цветом.

> **Статус.** Это спецификация для разработчика, а не отрисованные макеты. Значения контраста рассчитаны, но **не проверены инструментом на живой странице** — это шаг 5 задачи 0.9.

---

## 1. Принципы

**Государственная система, а не продукт.** Пользователь пришёл не за удовольствием, а за разрешением на выпас скота. Интерфейс не развлекает и не удивляет — он объясняет, где человек находится и что делать дальше.

**Половина пользователей заходит с телефона в поле.** Инспектор работает без связи, заявитель подаёт заявку из района. Плотность информации подчиняется этому, а не desktop-сценарию.

**Кириллица шире латиницы примерно на 15 %.** Кнопки и колонки, спроектированные под английский текст, ломаются на узбекском. Все размеры заложены с запасом.

**Ошибка — это не тупик.** По п. 4.1.7 сообщение обязано содержать причину, связанные данные, способ устранения и куда обращаться. Это формат, а не пожелание.

## 2. Цвет

### Основная палитра

Зелёный — отраслевая принадлежность, лес. Один основной цвет, один акцентный, нейтральная шкала.

| Токен | HEX | Где |
|---|---|---|
| `--color-primary-50` | `#F0F7F1` | Фон выделенных блоков |
| `--color-primary-100` | `#D9EBDC` | Фон при наведении |
| `--color-primary-300` | `#7FB98A` | Границы, второстепенные акценты |
| `--color-primary-600` | `#2E7D4F` | **Основной**: кнопки, ссылки, активные элементы |
| `--color-primary-700` | `#23653F` | Нажатие, наведение на кнопку |
| `--color-primary-900` | `#123522` | Текст на светло-зелёном фоне |

| Токен | HEX | Где |
|---|---|---|
| `--color-accent-600` | `#B45309` | Требует внимания, срок истекает, предупреждение |
| `--color-danger-700` | `#991B1B` | Наведение и нажатие на кнопку отказа |

### Нейтральная шкала

| Токен | HEX | Где |
|---|---|---|
| `--color-neutral-0` | `#FFFFFF` | Фон карточек и таблиц |
| `--color-neutral-50` | `#F8F9FA` | Фон страницы |
| `--color-neutral-200` | `#E4E7EA` | Границы, разделители |
| `--color-neutral-400` | `#9AA3AB` | Отключённое состояние, плейсхолдеры |
| `--color-neutral-500` | `#767F87` | **Границы элементов управления** — полей, кнопок, флажков |
| `--color-neutral-600` | `#5A646D` | Второстепенный текст, подписи |
| `--color-neutral-900` | `#1A1F24` | Основной текст |

### Семантические цвета

| Токен | HEX | Значение |
|---|---|---|
| `--color-success-600` | `#15803D` | Успех, соответствует, оплачено |
| `--color-warning-600` | `#B45309` | Предупреждение, приближается срок |
| `--color-danger-600` | `#B91C1C` | Ошибка, отказ, нарушение |
| `--color-info-600` | `#0369A1` | Информация, в обработке |

### Контраст

Рассчитанные коэффициенты для пар, которые встречаются в интерфейсе. Порог AA — **4.5:1** для обычного текста, **3:1** для крупного (от 18.66px полужирный или 24px обычный) и для границ элементов управления.

Значения ниже **пересчитаны по формуле WCAG 2.2** 10 августа 2026, а не оценены на глаз.

| Пара | Коэффициент | Проходит |
|---|---|---|
| `neutral-900` на `neutral-0` | 16.6 : 1 | AAA |
| `neutral-600` на `neutral-0` | 6.0 : 1 | AA |
| `neutral-0` на `primary-600` | 5.0 : 1 | AA |
| `neutral-0` на `danger-600` | 6.5 : 1 | AA |
| `neutral-0` на `success-600` | 5.0 : 1 | AA |
| `neutral-0` на `warning-600` | 5.0 : 1 | AA |
| `primary-900` на `primary-50` | 12.4 : 1 | AAA |
| `neutral-400` на `neutral-0` | 2.6 : 1 | **не проходит** — только для отключённых элементов, где текст не несёт смысла |

Пары, которых в первой редакции не было, но они встречаются в интерфейсе:

| Пара | Коэффициент | Проходит | Где |
|---|---|---|---|
| `neutral-0` на `info-600` | 5.9 : 1 | AA | Метки статусов в обработке |
| `neutral-0` на `accent-600` | 5.0 : 1 | AA | Предупреждения, истекающий срок |
| `neutral-600` на `neutral-50` | 5.7 : 1 | AA | Второстепенный текст на фоне страницы |
| `primary-600` на `neutral-0` | 5.0 : 1 | AA | Ссылки и активные элементы |
| `neutral-900` на `neutral-50` | 15.7 : 1 | AAA | Основной текст на фоне страницы |
| `primary-900` на `primary-100` | 10.8 : 1 | AAA | Текст на выделенном блоке |

Ни одна пара, несущая смысл, не опускается ниже порога AA. Единственная непроходящая — `neutral-400` на белом — применяется только к отключённым элементам, где текст дублируется другими средствами.

### Границы: два разных цвета для двух разных задач

Их легко перепутать, и ошибка стоит соответствия WCAG.

| Что | Токен | Требование |
|---|---|---|
| **Границы элементов управления** — поле ввода, кнопка, флажок, переключатель, селект | `--color-neutral-500` | Не менее **3 : 1** по WCAG 1.4.11. Даёт 4.07 : 1 на белом и 3.86 : 1 на фоне страницы |
| **Декоративные разделители** — линии между строками таблицы, границы карточек, обрамление блоков | `--color-neutral-200` | Порога нет: это не элемент управления, а оформление |

`neutral-200` на белом даёт **1.24 : 1**. Для разделителя это допустимо, для границы поля ввода — нет: человек со слабым зрением просто не увидит, где заканчивается поле.

### Правило, которое нельзя нарушать

> Цвет **никогда** не единственный носитель смысла (п. 4.1.7 ТЗ и WCAG 1.4.1).

Каждый статус несёт цвет **плюс** иконку **плюс** текст. Дальтоник и человек с чёрно-белым экраном должны понять состояние заявки одинаково.

## 3. Типографика

### Шрифт

Обязан содержать узбекскую кириллицу с символами `ў ғ қ ҳ`, латиницу и русский. Многие популярные шрифты их не содержат — проверять до выбора, а не после.

```
--font-family-base: "Inter", "Noto Sans", system-ui, -apple-system, sans-serif;
--font-family-mono: "JetBrains Mono", "SF Mono", Consolas, monospace;
```

Моноширинный — для номеров разрешений, серий, ЖШШИР, СТИР и сумм в таблицах: цифры одинаковой ширины выравниваются по колонке.

### Шкала

| Токен | Размер | Высота строки | Где |
|---|---|---|---|
| `--text-xs` | 12px | 16px | Подписи под полями, метки в таблицах |
| `--text-sm` | 14px | 20px | Второстепенный текст, ячейки таблиц |
| `--text-base` | 16px | 24px | **Основной текст**, поля ввода |
| `--text-lg` | 18px | 28px | Подзаголовки, важные значения |
| `--text-xl` | 22px | 30px | Заголовки разделов |
| `--text-2xl` | 28px | 36px | Заголовки страниц |
| `--text-3xl` | 36px | 44px | Главная страница публичного портала |

Минимум для текста, который читают, — **16px**. Поля ввода тоже 16px: на iOS меньший размер вызывает автоматическое масштабирование страницы при фокусе.

### Насыщенность

`400` обычный, `500` для подписей и меток, `600` для заголовков и кнопок. `700` не используется — на кириллице выглядит грязно при мелком кегле.

## 4. Отступы и размеры

Шкала кратна 4 — на ней хорошо сходятся и мелкие элементы, и крупные блоки.

```
--space-1: 4px     --space-6:  24px
--space-2: 8px     --space-8:  32px
--space-3: 12px    --space-12: 48px
--space-4: 16px    --space-16: 64px
```

| Токен | Значение | Где |
|---|---|---|
| `--radius-sm` | 4px | Метки, бейджи |
| `--radius-md` | 8px | Кнопки, поля, карточки |
| `--radius-lg` | 12px | Модальные окна, крупные панели |

### Размер элементов управления

| Элемент | Высота | Почему |
|---|---|---|
| Кнопка и поле, обычные | 40px | Комфортно мышью |
| Кнопка и поле, на мобильном | 48px | Минимум для пальца по WCAG 2.5.8 — 44×44 |
| Строка таблицы | 48px | Инспектор попадает пальцем в поле |
| Область касания иконки | 44×44px | Даже если сама иконка 20×20 |

## 5. Контрольные точки

| Точка | Ширина | Устройство |
|---|---|---|
| `mobile` | < 768px | Телефон, PWA инспектора |
| `tablet` | 768–1169px | Планшет |
| `desktop` | ≥ 1170px | **Целевой размер по ТЗ** |
| `wide` | ≥ 1440px | Рабочее место сотрудника, карта |

ТЗ требует безупречной работы **от 1170×768**. Ниже — работает, но плотность падает: таблицы превращаются в карточки, боковое меню сворачивается.

## 6. Статусы

Ключевая часть системы. 14 статусов заявки, 5 разрешения, 4 акта инспекции, 4 уведомления. У каждого — цвет, иконка, текст.

### Статусы заявки

| Статус | Цвет | Иконка | Подпись (uz-Cyrl) |
|---|---|---|---|
| `DRAFT` | нейтральный | карандаш | Қоралама |
| `SUBMITTED` | info | конверт | Юборилган |
| `IN_REVIEW` | info | часы | Кўриб чиқилмоқда |
| `PENDING_INFO` | warning | вопрос | Маълумот сўралган |
| `CONTRACT_DRAFT` | info | документ | Шартнома тайёрланмоқда |
| `RETURNED` | warning | стрелка назад | Қайтарилган |
| `APPROVED` | success | галочка | Тасдиқланган |
| `INVOICED` | warning | счёт | Тўлов кутилмоқда |
| `PAID` | success | монета | Тўланган |
| `PERMIT_ISSUED` | success | печать | Рухсатнома берилган |
| `REJECTED` | danger | крест | Рад этилган |
| `CANCELLED` | нейтральный | крест в круге | Бекор қилинган |
| `EXPIRED_UNPAID` | danger | часы перечёркнутые | Тўлов муддати ўтган |
| `CLOSED` | нейтральный | архив | Якунланган |
| `ARCHIVED` | нейтральный | коробка | Архивланган |

### Статусы разрешения

| Статус | Цвет | Иконка | Подпись |
|---|---|---|---|
| `ACTIVE` | success | щит | Амалда |
| `SUSPENDED` | warning | пауза | Тўхтатилган |
| `REVOKED` | danger | крест | Бекор қилинган |
| `EXPIRED` | нейтральный | календарь | Муддати тугаган |
| `ARCHIVED` | нейтральный | коробка | Архивланган |

### Компонент метки статуса

Всегда три части: точка цвета, иконка, текст. Никогда только цвет.

```
[●] [icon] Кўриб чиқилмоқда
```

На узком экране текст не прячется — сокращается сам контейнер, но подпись остаётся. Статус без подписи бесполезен.

## 7. Компоненты

Минимальный набор, из которого собираются все экраны. Каждый описан состояниями, потому что состояния — это то, что забывают.

### Кнопка

| Вид | Где |
|---|---|
| `primary` | Одно главное действие на экране. Больше одной primary-кнопки не бывает |
| `secondary` | Второстепенные действия |
| `ghost` | Действия в таблицах и карточках |
| `danger` | Удаление, отказ, аннулирование |

Состояния: обычное, наведение, нажатие, фокус, отключено, загрузка.

**Загрузка обязательна.** По п. 4.1.7 повторное нажатие не должно приводить к повторной отправке — кнопка блокируется и показывает индикатор в момент клика, а не после ответа сервера.

**Фокус виден всегда.** Обводка 2px цветом `primary-600` со смещением 2px. Убирать `outline` запрещено — это WCAG 2.4.7.

### Поле ввода

Части: метка, поле, подсказка, сообщение об ошибке, счётчик символов.

Требование п. 4.1.7 — в каждом поле отражаются наименование, формат, при необходимости пример, обязательность, допустимые значения и способ исправления ошибки.

```
Майдон (гектар) *
┌──────────────────────────┐
│ 12,5                     │
└──────────────────────────┘
Ўндан бир қисмигача, масалан 12,5
```

Обязательность — звёздочкой **и** атрибутом `aria-required`. Ошибка — красной рамкой **и** текстом **и** `aria-invalid`.

### Таблица

Рабочая лошадь: списки заявок, разрешений, платежей, актов.

- Заголовок закреплён при прокрутке
- Сортировка по колонке — стрелка показывает направление
- Плотность переключается: обычная 48px, компактная 36px
- Выбор строк чекбоксами для групповых действий
- На мобильном превращается в карточки, а не прокручивается вбок

**Пустое состояние обязательно.** Не пустой прямоугольник, а объяснение: почему пусто и что сделать. «Заявок нет. Подайте первую заявку» с кнопкой.

### Мастер подачи заявки

Отдельный компонент, потому что это самый ответственный экран системы.

Требования п. 4.1.7: индикатор прогресса, автосохранение, сохранение черновиком, возврат на предыдущий шаг, проверка перед окончательной отправкой, визуальное выделение обязательных полей, предупреждение о несохранённых данных.

```
① Вид деятельности → ② Участок → ③ Параметры → ④ Документы → ⑤ Проверка → ⑥ Подпись
```

Шаг, который нельзя пропустить: **⑤ Проверка**. Перед подписью ЭЦП пользователь видит итог — участок, период, поголовье, расчёт суммы с расшифровкой откуда она взялась.

### Карта

Слои, инструменты рисования, измерение, выбор базовой подложки, переключение системы координат, карточка контура, экспорт в PDF и PNG.

Отдельное состояние — **конфликт**: когда выбранный участок пересекается с занятым. Пересечение подсвечивается, рядом объяснение, какое разрешение занимает и до какой даты.

### Сообщение об ошибке

Формат из п. 4.1.7, четыре части:

```
⚠ Танланган контурда тасдиқланган норма йўқ

Ушбу контур бўйича фойдаланиш меъёри ҳали тасдиқланмаган.
Меъёрни тасдиқлаш — Тошкент ДЎХ норматив бўлими вазифаси.

Бошқа контурни танланг ёки техник кўмакка мурожаат қилинг: 71-207-07-70
```

Причина, с чем связано, что делать, куда обращаться. **Технический код не показывается** — он уходит в лог с `correlation_id`, по которому поддержка найдёт запись.

### Прочие компоненты

Селект с поиском, выбор даты и периода, загрузка файла с ограничением формата и размера, модальное окно, тост, вкладки, аккордеон, breadcrumb, боковое меню, пагинация, индикатор загрузки, скелетон.

## 8. Доступность

Уровень **AA по WCAG 2.2** — прямое требование п. 4.1.7. Проверяемые пункты:

| Требование | Как проверяем |
|---|---|
| Полная навигация с клавиатуры | Пройти весь сценарий подачи заявки без мыши |
| Видимый фокус | Обводка 2px, не убирать `outline` |
| Контраст | Инструментом, а не на глаз |
| Масштабирование до 200 % | Информация не теряется, горизонтальной прокрутки нет |
| Screen reader | Проверить на NVDA или VoiceOver |
| ALT и ARIA | На всех изображениях и интерактивных элементах |
| Ошибка не только цветом | Текст или иконка обязательны |
| Субтитры для видео | Видеоинструкции по ТЗ обязательны |
| Размер области касания | Минимум 44×44px |
| Порядок фокуса | Совпадает с визуальным порядком |

Порядок фокуса — то, что ломается чаще всего. При появлении модального окна фокус переходит внутрь и не выходит за пределы до закрытия.

## 9. Многоязычность

Первая очередь — узбекская кириллица. Структура допускает добавление латиницы, русского, каракалпакского и английского без переписывания (вопрос **О4**).

| Что учесть | Почему |
|---|---|
| Кириллица шире латиницы на ~15 % | Кнопки и колонки закладывать с запасом |
| Латиница и кириллица узбекского различаются длиной | «Рухсатнома» против «Ruxsatnoma» — почти одинаково, но не всегда |
| Даты в формате `дд.мм.гггг` | Принято в делопроизводстве |
| Числа: пробел разделяет разряды, запятая — дробную часть | `1 250 000,00 сўм` |
| Тексты в `locales/`, не в коде | См. инженерные стандарты, раздел 7 |

Ключи локализации английские: `application.status.in_review`, `errors.norm.not_published`.

## 10. Токены в коде

Всё выше живёт переменными, а не значениями в компонентах.

```css
:root {
  --color-primary-600: #2E7D4F;
  --color-neutral-900: #1A1F24;
  --text-base: 1rem;
  --line-height-base: 1.5;
  --space-4: 1rem;
  --radius-md: 0.5rem;
  --control-height: 2.5rem;
  --control-height-touch: 3rem;
}
```

Правило: **в компоненте не появляется ни одного HEX-значения и ни одного пикселя напрямую.** Только токены. Иначе через месяц палитра разъедется, а тёмную тему добавить будет невозможно.

## 11. Чего в системе нет намеренно

| Не делаем | Почему |
|---|---|
| Тёмная тема | ТЗ не требует, пользователи работают днём в офисе. Токены её допускают, но сейчас это лишняя работа |
| Анимации переходов между страницами | Отвлекают, замедляют, требуют `prefers-reduced-motion`. Оставляем только индикаторы загрузки |

# Дизайн внешнего API

Всё, что доступно снаружи: фронтенду, my.gov.uz и платёжным провайдерам. Внутренние вызовы между сервисами — в [`contracts.md`](contracts.md).

Этот документ нужен, чтобы фронтендер работал параллельно с бэкендом, а не ждал его.

---

## 1. Структура путей

```
/api/v1/*            фронтенд, аутентификация по JWT
/webhooks/{provider} платёжные провайдеры, аутентификация подписью
/bff/v1/*            my.gov.uz, mTLS и подпись
/public/v1/*         без авторизации: проверка QR, открытые данные
```

Маршрутизация — на nginx по префиксу, см. [`diagrams.md`](diagrams.md), схема 4.

### Версия в пути, а не в заголовке

`/api/v1/applications`. Причина простая: путь видно в логах, в браузере и в отчёте об ошибке. Заголовок приходится доставать отдельно, и при разборе инцидента это лишний шаг.

Ломающее изменение — новая версия. Старая живёт, пока есть потребители. Добавление необязательного поля ломающим не считается.

## 2. Ресурсы

Существительные во множественном числе, вложенность не глубже двух уровней.

| Метод и путь | Что делает |
|---|---|
| `GET /api/v1/applications` | Список заявок с фильтрами |
| `POST /api/v1/applications` | Создать заявку |
| `GET /api/v1/applications/{id}` | Карточка заявки |
| `PATCH /api/v1/applications/{id}` | Изменить черновик |
| `GET /api/v1/applications/{id}/timeline` | Единый timeline |
| `GET /api/v1/applications/{id}/calculation` | Расчёт с расшифровкой |
| `POST /api/v1/applications/{id}/submit` | Подписать и отправить |
| `POST /api/v1/applications/{id}/return` | Вернуть заявителю |
| `POST /api/v1/applications/{id}/approve` | Утвердить |
| `POST /api/v1/applications/{id}/reject` | Отказать |

### Переходы статусов — действия, а не PATCH

Смена статуса выражается отдельным ресурсом-действием, а не `PATCH {"status": "APPROVED"}`.

Причин три. Каждый переход требует своих данных: отказу нужны код `RJ-*` и правовое основание, утверждению — подпись ЭЦП. У переходов разные права: возвращать может сотрудник, утверждать только руководитель. И `PATCH` статуса создаёт иллюзию, что можно поставить любое значение, тогда как переходы ограничены статус-машиной из [`../tz/09-state-machines.md`](../tz/09-state-machines.md).

## 3. Формат ответа

### Одиночный ресурс

```json
{
  "data": {
    "id": "018f2e5a-...",
    "number": "A-00042",
    "status": "IN_REVIEW",
    "activity_type": "GRAZING",
    "period": { "from": "2026-05-01", "to": "2026-09-01" },
    "amount": "1250000.00",
    "created_at": "2026-09-15T10:30:00+05:00"
  },
  "meta": { "correlation_id": "018f2c..." }
}
```

### Список

```json
{
  "data": [ ... ],
  "meta": {
    "page": { "cursor": "eyJpZCI6...", "next_cursor": "eyJpZCI6...", "limit": 50 },
    "total": 1247,
    "correlation_id": "018f2c..."
  }
}
```

### Ошибка

```json
{
  "error": {
    "code": "ERR-NORM-002",
    "message_key": "errors.norm.limit_exceeded",
    "message": "Юклама қолдиқ лимитдан ошди",
    "details": {
      "remaining_sb": "18.50",
      "used_sb": "24.00",
      "max_allowed_heads": 15
    },
    "correlation_id": "018f2c..."
  }
}
```

Три уровня в ответе об ошибке. `code` — для кода клиента, `message_key` — ключ локализации, `message` — уже локализованный текст на языке запроса. `details` содержит то, что нужно показать пользователю по формату из п. 4.1.7: не только «лимит превышен», но и на сколько, и что можно.

Полный перечень кодов — [`../tz/14-errors-classifiers.md`](../tz/14-errors-classifiers.md).

## 4. Пагинация

**Курсорная, не по номеру страницы.** Списки заявок и разрешений постоянно пополняются; при `offset` записи начинают дублироваться и пропадать между страницами.

```
GET /api/v1/applications?limit=50&cursor=eyJpZCI6...
```

`limit` по умолчанию 50, максимум 200. Для экспорта — асинхронная выгрузка, а не увеличение лимита.

**Исключение — витрина прокурора.** Там нужны переходы к произвольной странице и общее число записей, поэтому дополнительно поддерживается `?page=`. Ограничение объёма экспорта остаётся (вопрос **П10**).

## 5. Фильтрация и сортировка

```
GET /api/v1/applications
    ?status=IN_REVIEW,PENDING_INFO
    &activity_type=GRAZING
    &territory_code=1027
    &period_from=2026-05-01
    &period_to=2026-09-30
    &assignee_id=018f2c...
    &sort=-created_at
```

Перечисление значений через запятую означает «или». Разные параметры — «и». Сортировка: минус перед полем означает по убыванию.

Поля фильтрации фиксированы для каждого ресурса и описаны в OpenAPI. Произвольных выражений нет — иначе невозможно гарантировать индексы и требование «поиск ≤ 3 секунды».

## 6. Аутентификация

| Канал | Как |
|---|---|
| `/api/v1/*` | `Authorization: Bearer <JWT>` |
| `/webhooks/{provider}` | Подпись провайдера в заголовке |
| `/bff/v1/*` | mTLS плюс подпись сообщения |
| `/public/v1/*` | Без аутентификации, с rate limit и CAPTCHA |

### JWT

Выдаётся `core` после входа через OneID, E-IMZO или логин с MFA. Внутри — `user_id`, `role`, `organization_id`, `territory_code`, `territory_scope`, срок жизни.

Время жизни: обычная сессия — 8 часов, **роль «Прокурор» — 30 минут** (п. 4.1.6). Обновление по refresh-токену, для прокурора обновления нет — только повторный вход с новой верификацией.

### Идемпотентность

Заголовок `Idempotency-Key` обязателен на `POST` и `PATCH`, меняющих состояние. Повторный запрос с тем же ключом возвращает результат первого.

```
POST /api/v1/applications
Idempotency-Key: 018f2c5a-draft-submit
```

Без этого двойной клик на «Отправить» создаёт две заявки — а по KPI ТЗ дубликатов должно быть ноль.

## 7. Коды состояния

| Код | Когда |
|---|---|
| `200` | Успех |
| `201` | Ресурс создан |
| `202` | Принято в обработку — асинхронный экспорт, импорт геометрии |
| `204` | Успех без тела |
| `400` | Некорректный запрос, `ERR-APP-001` |
| `401` | Не аутентифицирован, `ERR-AUTH-*` |
| `403` | Нет прав, `ERR-ACL-*` |
| `404` | Ресурс не существует |
| `409` | **Конфликт: дубликат заявки, `ERR-APP-002`** |
| `422` | Правило домена нарушено: `ERR-GIS-*`, `ERR-NORM-*`, `ERR-PAY-*` |
| `429` | Превышен rate limit, `ERR-AUTH-003` |
| `500` | Внутренняя ошибка, `ERR-SYS-001` |
| `502` | Внешний сервис вернул ошибку, `ERR-INT-002` |
| `503` | Сервис недоступен или ограниченный режим, `ERR-INT-001`, `ERR-SYS-002` |

Разделение `400` и `422` существенное. `400` — запрос неправильно составлен. `422` — запрос корректен, но нарушает бизнес-правило: участок занят, лимит превышен, нормы нет. Клиент обрабатывает эти случаи по-разному.

## 8. Особые эндпоинты

### Проверка лимита до подачи заявки

```
POST /api/v1/applications/check
{
  "activity_type": "GRAZING",
  "contour_id": "018f2c...",
  "geometry": { "type": "MultiPolygon", "coordinates": [...] },
  "period": { "from": "2026-05-01", "to": "2026-09-01" },
  "livestock": { "cattle_adult": 12, "sheep_over_6m": 40 }
}
→ 200
{
  "data": {
    "geometry_valid": true,
    "within_forest_fund": true,
    "conflicts": [],
    "fire_ban": false,
    "total_area_ha": "45.0000",
    "occupied_area_ha": "12.5000",
    "available_area_ha": "32.5000",
    "max_sb": "24.00",
    "active_permits_sb": "5.50",
    "remaining_sb": "18.50",
    "used_sb": "16.40",
    "within_limit": true,
    "amount": "1250000.00",
    "rule_version": "vmq689-2026-01"
  }
}
```

Ничего не создаёт, вызывается при каждом изменении параметров в мастере. Требование по времени — **≤ 5 секунд**. Ответ содержит всё для расшифровки суммы на шаге проверки.

### Публичная проверка разрешения

```
GET /public/v1/permits/verify?series=A&number=000042
→ 200
{
  "data": {
    "series": "A",
    "number": "000042",
    "issued_at": "2026-06-01",
    "valid_until": "2026-09-01",
    "forestry": "Тошкент ДЎХ",
    "activity_type": "GRAZING",
    "status": "ACTIVE",
    "signature_valid": true,
    "holder_masked": "М. У. Т."
  }
}
```

Персональные данные маскированы. Rate limit и CAPTCHA при большом числе автоматических запросов (сценарий С12). Требование по времени — **≤ 3 секунды**.

### Vector tiles

```
GET /api/v1/layers/{layer}/tiles/{z}/{x}/{y}.pbf
```

Генерация через `ST_AsMVT` прямо из PostGIS, кэш в Redis. Требование — отображение карты **≤ 3 секунд**.

### Асинхронные операции

Крупный экспорт и импорт геометрии не выполняются синхронно.

```
POST /api/v1/reports/{id}/export  → 202 { "task_id": "018f2f..." }
GET  /api/v1/tasks/{task_id}      → { "status": "RUNNING" | "DONE" | "FAILED", "result_url": "..." }
```

По готовности отправляется уведомление (сценарии С20, С21).

## 9. Ограничение частоты

| Область | Лимит |
|---|---|
| Публичная проверка QR | 30 запросов в минуту с адреса, дальше CAPTCHA |
| Открытые данные | 60 в минуту |
| Вход | 5 попыток, затем временная блокировка учётной записи |
| Обычный API | 300 в минуту на пользователя |
| Экспорт | 10 в час на пользователя |

Настраивается в nginx и Redis. При превышении — `429` и заголовок `Retry-After`.

## 10. Заголовки

| Заголовок | Направление | Назначение |
|---|---|---|
| `Authorization` | запрос | `Bearer <JWT>` |
| `Idempotency-Key` | запрос | Обязателен на изменяющих операциях |
| `Accept-Language` | запрос | `uz-Cyrl`, `uz-Latn`, `ru`, `kaa`, `en` |
| `X-Correlation-Id` | оба | Генерируется nginx, возвращается в ответе |
| `Retry-After` | ответ | При `429` и `503` |
| `X-RateLimit-Remaining` | ответ | Остаток лимита |

## 11. Что публикуется как схема

OpenAPI 3.1 для REST, AsyncAPI для событий — требование п. 4.2.9 ТЗ о ведении и версионировании интеграционных контрактов.

Схема **генерируется из кода**, а не пишется руками: FastAPI и Pydantic дают её автоматически, и она не может разойтись с реализацией. В CI проверяется, что схема не изменилась неожиданно — изменение контракта должно быть намеренным и попадать в diff.

Из схемы генерируется типизированный клиент для фронтенда. Ручное описание типов запросов и ответов на стороне Next.js не пишется.

## 12. Чего в API нет намеренно

| Не делаем | Почему |
|---|---|
| GraphQL | Один потребитель — наш фронтенд. Гибкость запросов не нужна, а гарантировать время ответа и индексы становится трудно |
| HATEOAS | Клиент один и знает маршруты. Ссылки в ответах увеличили бы объём без выигрыша |
| Пакетные операции | Ни один сценарий ТЗ не требует массовых действий над заявками |
| Вебсокеты | Обновление статусов через опрос раз в 30 секунд достаточно. Уведомления идут отдельным каналом |
| Мягкое удаление через `DELETE` | В системе нет удаления. Есть переход в `ARCHIVED` — это действие, а не метод |
